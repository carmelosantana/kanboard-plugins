# Matinee P1 (Foundation) Implementation Plan

> **For agentic workers:** use superpowers:subagent-driven-development. Every implementer and fixer is
> **Opus**, and every reviewer (task and whole-branch) is **Opus**. Pass `model:` explicitly on every dispatch.
> Never use Haiku. Steps use checkbox (`- [ ]`) syntax.

**Goal:** A Kanboard user can connect a Plex server with a token that is encrypted at rest and never rendered.
They can share chosen sections, or the whole server, with a project they manage, or (admins only) with
everyone. One policy class decides every ability. There is no playback yet. That is P2–P5.

**Method:** SDD, test-first.

**Spec:** `docs/specs/2026-11-19-matinee-plugin-design.md`. Read §1–§5, §9, §11 (security amendments) and
§12. The spec is the source of truth for every value this plan doesn't repeat. The decision map is
`docs/research/2026-11-19-matinee-decision-map.md`.

**Architecture:**
- `Crypto/`:
  - `KeyStore` resolves the root key from env or the key file.
  - `Subkeys` derives subkeys from it.
  - `TokenBox` seals and opens tokens with AD.
- `Http/`:
  - `UrlGuard` is the SSRF guard, ported from AiConnector.
  - `PlexTransport`, `CurlTransport` (pinned, no redirects) and `FakeTransport` (Test/support) move bytes.
  - `PlexClient` returns whitelisted parsing of `/identity` and `/library/sections`.
  - `PlexScrub` strips tokens.
- `Model/`:
  - `ServerModel` (connect, verify, update, remove, `tokenFor` as the single decrypt site).
  - `ShareModel` (CRUD for shares and their sections).
  - `SharePolicy` (pure abilities).
  - `Settings` (the config keys).
- `Controller/`:
  - `MatineeServerController` for user settings servers and shares.
  - `MatineeAdminController` for admin settings and the server list.
- `Template/`: plain PHP views. `Schema/`: four drivers.

**Tech stack:** PHP 8.4, ext-sodium, ext-curl, Kanboard 1.2.47 (PicoDb, Pimple), and PHPUnit through
`testing/run-plugin-tests.sh`.

## Global constraints

**Plugin shape**
- The plugin is `Matinee`, namespace `Kanboard\Plugin\Matinee`, at `Matinee/` in the harness. The directory
  is its own git repo on branch `main`.
- Version `0.1.0`, MIT, author Carmelo Santana, homepage `https://github.com/carmelosantana/kanboard-matinee`.
- `plugin.json`: `kanboard_version >=1.2.47`, `php_version >=8.4`, `requires: []`, `recommends: []`.

**Repo and release**
- Don't create a GitHub repo. Don't push or tag. Don't edit `kanboard-modmenu-directory`.
- `.github/workflows/release.yml` and `test.yml` are copied verbatim from `templates/workflows/`.

**Secrets**
- No real Plex token anywhere. Tests use the fake token `test-token-NOT-REAL-0000` and fake URLs
  (`https://plex.example.test:32400`, with DNS replaced through the resolver seam).
- The token appears only in the `X-Plex-Token` header built in `PlexClient`, and as plaintext only inside
  `TokenBox::open`/`seal` and `ServerModel::tokenFor`.
- No `getMessage()`, log line, flash, template or exception may contain it, or any URL query.
- Every function parameter that carries a token or key is marked `#[\SensitiveParameter]`.

**Requests and templates**
- Every state change is a POST checked with `$this->checkCSRFForm()`.
- ACL comes from `$this->applicationAccessMap` / `projectAccessMap` rules registered in `Plugin::initialize()`.
  Controllers also check `SharePolicy` explicitly, so ownership is never left to ACL alone.
- No inline JS or CSS. P1 needs no JS.
- Templates escape everything with `$this->text->e()`.

**Platform**
- If `extension_loaded('sodium')` or `extension_loaded('curl')` is false, `initialize()` registers only an
  admin notice through `template:layout:top` and returns.

**Process**
- TDD. Before each task's commit, run the **full** suite to completion: `./testing/run-plugin-tests.sh --all`.
- Commits are small and carry no AI attribution.
- Never use the `kanboard` / `kanboard-admin` MCP tools for writes. They point at production.

## Review focus

1. A token can't reach output: a test renders every Matinee template and runs every exception path with the
   fake token, then greps the output (Task 9).
2. DNS rebinding: the guard runs on every request, and the transport is pinned to the checked IP (Tasks 4
   and 6).
3. A non-owner can't touch someone else's server or share by id (IDOR). Tasks 7–9 cover this.
4. The key file is never overwritten, and its permissions are right (Task 2).

### Task 2: KeyStore and Subkeys

Spec §2. **Files:** `Crypto/KeyStore.php`, `Crypto/Subkeys.php`, `Crypto/CryptoException.php`,
`Test/KeyStoreTest.php`.

**Interfaces:**
- `KeyStore::__construct(string $dir, ?string $envValue)`. `rootKey(): string` returns 32 bytes.
  `keyId(): string` returns `env` or `file`.
- `Subkeys::token(string $root): string` and `Subkeys::refs(string $root): string`, using contexts
  `mtntoken` and `mtnrefs_`.

Amendment S12, binding:
- Create the file with `fopen($path, 'x')` under an `flock` on `$dir/.lock`, then re-read it and use the bytes on disk.
- Add `keyIdFor(string $root): string`, the first 8 hex chars of `sodium_crypto_generichash('mtn-kid', $root)`.
- Add `allKeys(): array<keyId, rootKey>` (env and file, whichever exist).
- Add `activeKeyId(): string`, which is the env key when set.

- [ ] Tests (the dir is a per-test temp dir), plus: `allKeys` holds both when both exist; the key id is stable and differs per key;
  - creates the file at 0600 and the dir at 0700;
  - a second instance returns the same key;
  - a wrong-size file throws and is left byte-identical;
  - a valid env key wins and `keyId` is `env`;
  - bad base64 or a wrong-length env value throws and no file is created;
  - the two subkeys differ from each other and from the root.
  - Mutations to kill: dropping the `chmod`, writing over an existing file, swapping the contexts.
- [ ] Run (FAIL), implement (`umask`-safe `mkdir 0700`, `flock`, `fopen 'x'`, `chmod 0600`, re-read), then run (PASS)
  and `--all`. Commit.

### Task 4: UrlGuard

Spec §3, §11. **Files:** `Http/UrlGuard.php`, `Http/UnsafeUrlException.php`, `Test/UrlGuardTest.php`.

**Interfaces:** the same as `AiConnector/Model/UrlGuard.php`, with these changes:
- Config keys `matinee_allowed_hosts` and `matinee_private_targets` (S1: no blanket private opt-in).
- `__construct(array $allowedHosts = [], array $privateTargets = [])`. A private address passes only if it matches a target entry (`host`, `ip`, `cidr`, each with an optional `:port`).
- Ports are limited to 32400, 443 and 80 unless the matching target names another.
- IPv4 embedded in `::ffff:0:0/96`, `::ffff:0:0:0/96`, `64:ff9b::/96` and `64:ff9b:1::/48` is classified as its IPv4. `fec0::/10` is blocked (S8).
- `isValidBaseUrl(string): bool`: http/https only, a host, no userinfo, query or fragment, path empty or `/`.
- `normaliseBaseUrl(string): string`: `scheme://host[:port]`, lowercase host.
- `check(string $url): array{host, port, ip}` (`port` is the effective port: explicit, else 443 or 80).
- `setResolverForTesting(?callable)`.
- Plus the amendments from §11.

- [ ] Table test of the §12 UrlGuard cases, as amended by S1 and S8:
  - private refused without a target; passes with a matching host, CIDR or IP target; refused on a port the target doesn't name;
  - port 22 to a public host refused;
  - `::ffff:10.0.0.1`, `::ffff:169.254.169.254`, `64:ff9b::a9fe:a9fe` and `fec0::1` refused;
  - a resolver answering public then private: the second check refuses.
  - Mutation to kill: removing `169.254.0.0/16` from the blocked list.
- [ ] Run (FAIL), port and implement, run (PASS), then `--all`. Commit.

### Task 6: CurlTransport

Spec §3. **Files:** `Http/CurlTransport.php`, `Test/fixtures/fake-plex/index.php`, `Test/CurlTransportTest.php`.

**Interfaces:** `CurlTransport::__construct(UrlGuard $guard, int $connectTimeout = 5, int $timeout = 15, int $maxBytes = 8388608)`,
implementing `PlexTransport`.

Amendments, binding:
- S8: resolve `host:{effectivePort}:{ip}` (IPv6 `[ip]`), `CURLOPT_PROXY=''`, `CURLOPT_NOPROXY='*'`, `CURLOPT_PROTOCOLS_STR`/`REDIR_PROTOCOLS_STR` `http,https`, and abort when `CURLINFO_PRIMARY_IP` != the pinned IP.
- S9: never set `CURLOPT_VERBOSE` or `CURLINFO_HEADER_OUT`; headers are `#[\SensitiveParameter]`.
- S11: the default `maxBytes` is 2 MiB (2097152).

- [ ] Tests:
  - A `php -S 127.0.0.1:<free port>` fixture is started in `setUpBeforeClass` and killed in teardown. It
    answers `/identity`, `/library/sections`, `/redirect` (302 to `/identity`) and `/big` (9 MiB).
  - The guard needs a private target `127.0.0.1:<port>` and a resolver mapping `plex.example.test` → `127.0.0.1`.
  - Cases:
    - a request to `http://plex.example.test:<port>/identity` reaches the fixture through the pin, which

### Task 7: ServerModel

Spec §4, §2. **Files:** `Model/Settings.php`, `Model/ServerModel.php`, `Test/ServerModelTest.php`.

**Interfaces:**
- `Settings`: constants `CONNECT_POLICY` (`matinee_connect_policy`: `everyone` | `admins`), `ALLOWED_HOSTS`,
  `ALLOW_PRIVATE` and `CLIENT_ID`. `clientId()` lazily creates a uuid.
- `ServerModel` is a container service `matineeServerModel`.
  - `connect(int $userId, string $name, string $url, string $token): int`
  - `update(int $serverId, int $actorId, string $name, string $url, ?string $token): void`
  - `verify(int $serverId): string` (returns the status)
  - `remove(int $serverId, int $actorId): void`
  - `setEnabled(int $serverId, bool $on, int $actorId): void` (admin only)
  - `get(int $id): ?array` (never includes the token columns)
  - `listForOwner(int $userId)`, `listAll()`
  - `tokenFor(array $server): string`
  - `clientFor(array $server): PlexClient`
- Schema v2 (all four drivers) adds `matinee_attempts(user_id FK CASCADE, created_at INTEGER)`, indexed on (`user_id`, `created_at`). It backs S1's 10-per-10-minutes limit (connect and verify each count as one; rows older than 1 h are pruned on insert). `Settings` adds `ATTEMPT_LIMIT` (10), `ATTEMPT_WINDOW` (600) and `MAX_SERVERS` (3).
- `matinee_servers.key_id` holds `KeyStore::keyIdFor`. `tokenFor` opens with that key and re-seals with the active key when they differ (S12).
- Every connect, verify or update failure surfaces as the single `MatineeConnectException('matinee.connect_failed')` (S1). The stage is logged through `$this->logger->info` with the host only.
- `tokenFor` and `clientFor` refuse when the owner is inactive (S6).
- A `PlexClient` factory is injectable (`$container['matineePlexClientFactory']`) so tests use `FakeTransport`.

- [ ] Tests:
  - connect stores the row, and a full-table string scan finds no fake token;
  - connect with a bad URL, a 401 or an unreachable server stores nothing;
  - the `admins` policy refuses a user;
  - an update with a new URL and a null token is refused (`matinee.token_required`);
  - an update with a machine-id change is refused without a token;
  - `remove` by a non-owner and non-admin is refused;
  - an admin can disable but `get` never returns the token columns;
  - tampered ciphertext → `tokenFor` throws, and the status becomes `reconnect`;
  - a DB-only change of `base_url` makes `tokenFor` fail (S7);
  - the 11th attempt within 10 minutes is refused, and so is a 4th server;
  - every failure stage gives the same exception message;
  - a row sealed under the file key re-seals to the env key on open;
  - a disabled owner → `tokenFor` refuses.
  - The duplicate-server check and the server limit compare host plus **effective** port: `http://h` and `http://h:80` are the same server (UrlGuard review M4).
  - Mutation to kill: `get()` selecting `*`.
- [ ] Run (FAIL), implement, run (PASS), then `--all`. Commit.
