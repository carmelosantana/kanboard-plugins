# Chicane v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. SDD model rule: implementer/fixer = **Opus**, reviewer = **Opus** (task and whole-branch); pass `model:` on every dispatch; never Haiku.

**Goal:** Ship the Chicane Kanboard plugin. It renders a project as an isometric race track on a standalone members-only or share-token page, with map-only redaction and a JSON summary for Chat.

**Architecture:**
- PHP builds a project "race state" from core models. Optional feeds come from Presence, Agents and TimeReport.
- PHP redacts the state on the server for map-only mode and serves it as JSON to a bare page.
- An engine-agnostic JS track model (ported from the prototype) turns the state into geometry. A PixiJS + GSAP renderer draws it isometrically.
- Polling and a since-last-visit replay animate the changes.

**Tech Stack:**
- Kanboard 1.2.47 plugin, PHP ≥ 8.4, buildless.
- PHPUnit through `testing/run-plugin-tests.sh`.
- Zero-dependency `node --test` for JS.
- PixiJS 8.22.0 + GSAP 3.15.0 (MotionPathPlugin), vendored.

**Spec:** `docs/specs/2026-10-22-chicane-v1-design.md`. Prototype reference: `ChicanePrototype/` on branch `prototype/chicane` @ 5d97fe9 (`Assets/shared/track.js`, `Assets/a/renderer.js`, `tools/snapshot.sh`). Read it, don't copy it verbatim.

## Global Constraints

- Plugin dir `Chicane/`, namespace `Kanboard\Plugin\Chicane`, own git repo (`carmelosantana/kanboard-chicane`). Harness changes are committed in the `kanboard-plugins` repo.
- Buildless: no bundler. Classic `<script>` tags. Globals: `window.Chicane` (track model), `window.ChicaneLive` (polling/replay), `window.ChicaneHud` (HUD), `window.ChicaneRace` (renderer).
- Runs under Kanboard's default CSP `default-src 'self'; style-src 'self' 'unsafe-inline'; img-src * data:`. Never call `setContentSecurityPolicy()`, no CDN, no blob workers.
- Project metadata keys:
  - `chicane.visibility`: `off|members|public|map_only`, default `off`
  - `chicane.token`: 64 hex chars from 32 random bytes
  - `chicane.window_days`: default `30`
  - `chicane.units`: `subtask|complexity`, default `subtask`
- Constants:
  - poll interval 20 s
  - stalled = idle ≥ 3 days
  - recent comment = < 48 h
  - car speed `520 / (1 + 160·|curvature|)` px/s
  - turn radius ≥ 1.15 × half road width
- Hazard types (exact strings): `pothole`, `debris`, `wreck`, `slick`.
- Summary JSON keys (exact): `project_id`, `progress_pct`, `distance_to_finish`, `cars` (each `{user, task_id}`), `updated_at`.
- Map-only never sends task titles, comment text, real user names, usernames, tag names or swimlane names. Users become initials, swimlanes `Lane N`, and the summary's `task_id` is `null`.
- Original art only (no third-party IP or PII in assets). Every animation eases. `prefers-reduced-motion` means no fly-in and transitions of 0.3 s.
- Supply chain: run `/powerup:supply-chain` before vendoring PixiJS/GSAP (Task 7).
- Commits: no AI attribution lines.

## Review Focus

1. **Empty race:** a project with zero tasks in the window should render "No laps yet" with no NaN or JS error. Tested in Task 6 (`buildEmptyState`) and Task 9 (HUD).
2. **Names leaking through side fields in map-only:** swimlanes on Beige Bullet are named after people ("Carmelo", "Codex"), and tags can carry names. Map-only must rename lanes `Lane 1..N` and drop tags (hazards needing `wontfix` are resolved on the server first). Tested in Task 5.
3. **Hostile titles on a public page:** a title like `<img src=x onerror=alert(1)>` must show as text. Tested in Task 9 (HUD uses `textContent`; test asserts no element is created).
4. **Token rotated while a public page is open:** the next poll gets 404, and the page should stop polling and show "This race link has expired." Tested in Task 9.
5. **Orphans:**
   - A task owned by a user no longer in the project gets no car and no crash.
   - A task in an inactive swimlane goes in lane 0.
   - A subtask with no assignee earns no XP.

   Tested in Task 4 and Task 6.

### Task 6: Track model

**Files:**
- Create: `Chicane/Assets/js/track.js`, `Chicane/Test/js/track.test.mjs`

**Interfaces:**
- Consumes: the state shape (Task 4/5), including `task.wontfix`.
- Produces `window.Chicane` with:
  - `build(state, {mode:'subtask'|'complexity'}) → model`
    - `model` = `{path:{points:[{x,y,s,heading,curv,kind:'turn'|'straight',seg,done}],length,step}, segments:[{index,taskId,title,column,open,lane,units,doneUnits,s0,s1,blocked,comments,ownerId}], lanes:[{id,name,offset}], roadWidth, laneWidth, cars:[{userId,name,initials,isAgent,online,level,xp,lane,s,inPits,taskId,taskTitle,color}], spectators:[{taskId,s,side,row,recent}], barriers:[{taskId,s,lane}], hazards:[{type,taskId,s,lane?,side?,days?,level?,radius?}], totalUnits, doneUnits, progress, progressS, finishS, turns}`
  - `sample(path, s)`, `offset(pt, d)`
  - `morph(fromModel, toModel, t) → path`, aligned by task (see below)
  - `speedAt(curv)`
  - `UNIT = 60`
- Port the algorithm from `ChicanePrototype/Assets/shared/track.js`:
  - ordering, layout with permanent turns (lead-in straight `0.4·UNIT`, sweeper `0.25–0.55` rad, chicane `0.4–1.0` rad over 4 steps of `0.35·UNIT`, row guard at 1.75 rad)
  - centripetal Catmull-Rom resampling every 4 px, curvature over ±3 samples
  - **Change from the prototype:** each turn step's length becomes
    `max(0.35·UNIT, 1.15·(roadWidth/2)·mag/4)`. This keeps the radius ≥ 1.15 × half the road for any lane
    count; the prototype's fixed step only held for 4 lanes.
  - the hazard rules, cars, spectators and barriers
- Drop the prototype's `mutate` and its mocked online/XP.
  - `online`, `xp`, `level` and `isAgent` come from the state: `users[].online/xp/level` and `agent_uids`.
  - `level` stays `null` when the state has `null`.
- **Morph by task (Decision 16):**
  - For each task id in both models, interpolate its points by fraction within that segment.
  - A task only in `to` grows from a zero-length point at its predecessor's end.
  - A task only in `from` shrinks to a point.
  - The output path is rebuilt in `to` order and `s` is recomputed.
